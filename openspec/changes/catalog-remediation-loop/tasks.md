## Cross-Cutting Constraints (all slices)

- Strict TDD: fixtures in `src/js/tests.js` FIRST (RED), then implementation (GREEN), then corpus/refactor verification (REFACTOR). Register every new fixture group as `this.testXxx()` in `Tests.runAll()`.
- Runner: `npm test` (= `node scripts/run-tests.js`) for unit suites; `npm run lint` (= `eslint src/js/ scripts/ --max-warnings 200`) for lint; FASE 2 gates via `node scripts/measure-model-quality.js` and `node scripts/measure-extraction.js`.
- Every new module keeps the browser-global + CommonJS convention (`if (typeof window !== 'undefined') window.X = X; if (typeof module !== 'undefined') module.exports = X;`).
- UI strings / `qualityReason` warnings stay Spanish; `remediationEvidence` keys stay English and stable.
- No OCR, no LLM/provider usage, no non-deterministic remediation, no parser rewrite, no storage/migration changes. Stored catalogs untouched — remediation is an in-memory read-only post-processing layer over extraction.
- FASE 2 measurement scripts (`scripts/quality/ground-truth.js`, `scripts/measure-model-quality.js`, `scripts/measure-extraction.js`) are never modified.
- **Hard success criterion (owner-confirmed):** GREEN ≥ 99% measured on the catalog-eligible corpus n = 2261 (2309 − 48 import-filtered RED) → target ≥ 2239 GREEN. The 48 RED are bounded-irremediable, tracked in the ledger and the human-review report.
- **Rollback:** every remediation strategy and calibration rule is config-gated (`config.remediation = { enabled, strategies: {...} }` via `src/js/remediationConfig.js` + optional repo-root `remediation-config.json` deep-merge). Flipping a strategy off, or `enabled:false`, restores prior behavior (measure-only). Full rollback = config flip + reverting the remediation file set; no storage/migration delta exists.
